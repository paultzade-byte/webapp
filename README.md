# Halo Djangogo! — антизлісний клікер

Спільний realtime-клікер з прихованим виграшним кліком.

## Правила

1. **Запас.** У кожного 20 кліків на гру.
2. **Депозит.** Перші 10 кліків — депозит: вони не рухають загальний лічильник і не можуть
   виграти. На кожному депозитному кліку може випасти підвох:
   🏃 кнопка вислизає (клік не зараховано), 💥 «щось пішло не так» на весь екран,
   🔒 кнопку заклинює на 2 с.
3. **Бій.** Після депозиту кліки рухають спільний лічильник. Сервер сховав один виграшний
   клік десь між 1 і 15 — хто на нього влучить, той переміг.
4. **Простій.** Не клікаєш 5 с — мінус клік. У бою він *згорає*: рухає лічильник за тебе,
   але виграти не може. Згорів виграшний — його перезагадують у наступних 15.
   Таймер стартує з твого першого кліку.
5. **Карти.** За 5-й і 15-й клік — випадкова карта (в руці максимум одна):
   🔋 +3 кліки, 🗡 гравець −2 кліки, 🔄 обмін запасом з гравцем,
   🛡 щит (таємний, блокує наступний саботаж/обмін/штраф).
6. **Кінець.** Хтось влучив — переміг. У всіх скінчились кліки — нічия.

## Запуск

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver 0.0.0.0:8000
```

Redis не обов'язковий. Без нього працює in-memory channel layer (тільки для одного процесу).
Щоб підключити Redis: `REDIS_URL=redis://127.0.0.1:6379 python manage.py runserver`.

Інші змінні: `GAME_TARGET_MAX` (діапазон виграшного кліку), `DJANGO_ALLOWED_HOSTS`, `DJANGO_DEBUG`, `DJANGO_SECRET_KEY`.

Тести: `python manage.py test tasks`

## Як це влаштовано

| Файл | Що там |
|---|---|
| `tasks/game.py` | **Всі правила гри.** Звичайні sync-функції: `join`, `click`, `play_card`, `tick`, `new_game`, `snapshot`. Почни звідси. |
| `tasks/consumers.py` | WebSocket: приймає дії, викликає `game.*`, розсилає стан усім. Протокол описано зверху файлу. |
| `tasks/models.py` | `Game` (раунд; найновіший = поточний; `secret` ніколи не йде клієнтам) і `Player` (запас, депозит, карта, щит). |
| `tasks/static/tasks/js/app.js` | Весь клієнт. Сервер — джерело правди, клієнт тільки малює. |
| `config/settings.py` → `GAME` | Крутилки: запас, депозит, діапазон, шанс пасток, карти, таймаути. |

`GET /api/state/` повертає той самий стан, що й WebSocket — зручно для `curl`.

Штраф за простій рахується «ліниво» з часових міток (`_settle_idle`), тож тікер у consumer —
лише щоб усі бачили штрафи одразу. Якщо його вимкнути (`TICK_SECONDS = 0`), правила не зміняться.

## Ідеї, що можна покрутити

- Більше карт: «заморозка» суперника на 3 с, «рентген» (показує, в кого щит).
- Кімнати: `ws/game/<room>/` і окремий `Game` на кімнату.
- Ачівки («пройшов депозит без жодної пастки», «спалив виграшний клік»).
- Ботик-гравець, який грає за простою стратегією — і перевірити, чи її можна обіграти.
